# 完整验证样例

## 初始条件

已经安装并启动配套服务；正式验收还需要导入并发布 Dify Workflow、配置模型服务和五个工作流环境变量。首次使用一个从未出现过的随机玩家暗号，例如 `reviewer_2026_01_X7`。如该暗号以前用过，请换一个，避免复用旧存档。

没有预置数据和知识库。后端会自动创建 Scope；最初没有 atomic-memory Artifact、回忆、道具或结局。不要把旧 `.runtime` 复制进评审环境。

## 样例A：回忆寄存、三轮剧情与跨会话回访

所有步骤填写相同玩家暗号。Dify Workflow 每次执行都是独立运行；使用新 WebApp 标签页或新的 API user 仍应恢复相同进度。

| 步骤 | 输入 | 预期表现 | 可核对证据 |
| --- | --- | --- | --- |
| 1 | 开场 | 第1周目、0/3、无回忆，展示“会下雨的收银机”与3个选项 | prepare 输出 artifact 为 null；只创建Scope，没有剧情状态变更 |
| 2 | 寄存：奶奶在蓝铁盒里藏了一颗橘子糖 | AI 回应蓝铁盒/橘子糖，面板显示完整回忆，仍为0/3 | commit 返回atomic-memory真实ID、revision=1 |
| 3 | 1 | 获得晴天小票，温暖2、1/3，进入倒着走的猫 | 同一Artifact revision=2 |
| 4 | 1 | 获得猫爪车票，温暖4、2/3，进入第三扇门 | revision=3 |
| 5 | 1 | 获得回声钥匙、温暖6、3/3，结局“灯火守夜人” | revision=4，面板有3件道具 |
| 6 | 新开会话，输入回访 | 记得蓝铁盒、橘子糖与过去的选择，仍为3/3，收藏保留 | prepare 的 memory_read 仍是同一Scope、同一Artifact revision=4 |
| 7 | 新周目 | 第2周目、0/3，道具清空，回忆和“灯火守夜人”收藏保留 | revision=5 |

开放式台词没有唯一标准答案；正式状态面板和记忆引用是确定的。AI 台词应具体回应当前行动、复用已给记忆，不应伪造未提供的玩家历史。

## 样例B：另外两种结局和即兴补充

分别使用全新的玩家暗号。连续三次输入2，获得“宇宙整活王”；连续三次输入3，获得“月光合伙人”。任意一次可输入 `2：我给乌云开一张月亮味的罚单`，规则仍按选2，AI 台词应回应补充内容。

## 样例C：隔离、失败与复测

- 换一个全新暗号输入回访：必须没有其他玩家的回忆与进度。
- 模型地址临时改成无效地址，在一份已有存档上输入1：模型节点失败。恢复模型地址后输入回访，进度应与失败前相同。不要只看网页报错来推断写入情况。
- 同一旧版本准备两个回合并依次提交：第一个成功，第二个409，不能互相覆盖。此项由 `scripts/acceptance.py` 自动执行。
- 完成存档后停止并重启 PowerContext 与后端，保持 `.env` 和数据目录不变，使用相同暗号回访：恢复同一存档。自动测试会实际重启两进程。
- 重复验证时换一个随机暗号；不用删除原数据。要继续原故事则保持暗号。

## 自动验证与证据状态

配置发布后的Dify API，在.env填写DIFY_API_URL和DIFY_APP_API_KEY，执行 `scripts/verify_workflow.py`。它会实际调用Dify引擎和模型服务，生成 `evidence/workflow.json`；不会模拟模型或把本地CPython执行当作Dify运行。

`scripts/acceptance.py` 用于独立的PowerContext/API规则与重启测试，其调试记录保存在被Git忽略的.runtime目录，不作为正式Dify证据。正式证据不包含机器路径、服务地址、密钥、玩家取档暗号或进程信息。
